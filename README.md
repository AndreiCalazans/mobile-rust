# mobile-rust — a Rust-core mobile PoC

A proof of concept: a mobile app whose **entire business logic lives in Rust**.
SwiftUI (iOS) and Jetpack Compose (Android) render state and send intents; they
hold no logic. The FFI bridge code (JNI/Kotlin on Android, Swift/ObjC on iOS)
is **auto-generated by [UniFFI](https://mozilla.github.io/uniffi-rs/) and
gitignored** — it is regenerated on every build and never committed.

## Where the boundary sits

In the reference architecture the `NATIVE · SWIFT / COMPOSE PER PLATFORM` line
moves up **above** *Use cases*. Everything below it is Rust:

```
SwiftUI / Compose        View + ViewModel        native, no logic
------------------------ FFI boundary (UniFFI, generated) --------------
AppCore                  use-case facade         Rust
UserRepository           session source of truth Rust
dictionary / graphql     data sources            Rust
transport                shared HTTP client      Rust
```

Native code holds exactly one object — `AppCore` — and calls its methods.

## What the PoC does

- **Fake session** — `login(displayName)` fabricates a user + token;
  `logout()`, `currentSession()`, `currentUser()`.
- **Dictionary (REST)** — fetches a set of words from
  [dictionaryapi.dev](https://dictionaryapi.dev) via `defineWords([...])`.
- **Bitcoin (GraphQL)** — `fetchBitcoin()` runs a GraphQL query against
  `graphql.coinbase.com/query` (same pattern as `~/coinbase/research-mobile-app`).
  The generic `graphql::query()` helper means the Rust layer supports arbitrary
  GraphQL requests, not just this one.

All network calls are `async` in Rust and surface as Kotlin `suspend` /
Swift `async throws`.

## Layout

```
rust/                 the whole app — logic only
  src/
    model.rs          value types crossing the boundary (Record / Enum / Error)
    transport.rs      shared reqwest client
    dictionary.rs     REST data source
    graphql.rs        GraphQL client + typed bitcoin/asset fetch
    user_repository.rs fake session + user source of truth
    lib.rs            AppCore — the UniFFI-exported use-case facade
  examples/smoke.rs   live end-to-end check (REST + GraphQL)
  build-android.sh    build .so + regenerate Kotlin (gitignored)
  build-ios.sh        build XCFramework + regenerate Swift (gitignored)

androidApp/           Jetpack Compose, consumes generated uniffi.app_core
iosApp/               SwiftUI, consumes generated app_core module

spike/                the earlier bridge-generation spike (see spike/CONSUMPTION.md)
docs/                 feasibility write-up
```

## Building

Prereqs: Rust (`rustup`), and per platform:

```bash
# Android
rustup target add aarch64-linux-android armv7-linux-androideabi \
                  x86_64-linux-android i686-linux-android
cargo install cargo-ndk        # needs Android NDK

# iOS
rustup target add aarch64-apple-ios aarch64-apple-ios-sim x86_64-apple-ios
```

Then the native build systems invoke the Rust build automatically:

- **Android** — the `:app` Gradle module runs `rust/build-android.sh` before
  Kotlin compilation (see `androidApp/app/build.gradle.kts`).
- **iOS** — add `rust/build-ios.sh` as a Run Script build phase before
  "Compile Sources", and link `iosApp/Generated/AppCore.xcframework`.

To run the logic without a device:

```bash
cd rust
cargo test               # unit test: fake session
cargo run --example smoke   # live REST + GraphQL
```

## Auto-generated + gitignored bridge

Confirmed feasible; see [`docs/feasibility-bridge-codegen.md`](docs/feasibility-bridge-codegen.md).
`uniffi-bindgen` is embedded in the crate behind the `bindgen` feature and runs
against the compiled library to emit Kotlin and Swift. The output lands in
`androidApp/app/build/generated/uniffi` and `iosApp/Generated`, both gitignored.
Because the bindings are a deterministic function of the Rust API and are
regenerated every build, they can never drift.
